
Если мы добавляем недостающую функциональность во фреймворк CRAILS:

- Добавить сначала в локальные шарды
- Проверить работу
- Перейти в ~/myshards/
- Найти соответствующий шард
- Внести туда патч
- Опубликовать патч с bump version формата vX.Y.Z
- Перейти в crails/текущий проект в зависимости от надобностей изменений
- Подтянуть опубликованный шард с версией vX.Y.Z
- Протестировать изменения снова
- Собрать rake build:crails для проверки на баги сборки и возможные косяки до рантайма
- Коммит и пуш если всё прошло хорошо


Хелперы должны располагаться в app/helpers/ всегда, никогда в контроллерах, если видишь такое, то это неправильно

Инлайн авторизация и дублирование в контроллерах недопустимо, используй `before_action :function`, затем 

```ruby
def function
  # some actions here
end
```

Таким образом код не будет разрастаться в контроллерах. Это best practices

Не используй плоские классы контроллеров, если у нас есть неймспейс, если ты видишь такое в проекте - сообщи, это нарушение стиля
Плоский = без папки. `controllers/<namespace>/my_controller.cr` ok, `controllers/namespace_my_controller.cr` - wrong. 


Выполненные планы переноси в plans/completed/


После любых изменений прогони twinshot review default


Старайся также сохранять код по стилю 1 к 1 с Rails оракул, если что-то не получается реализовать - добавляй это в записки notes/ либо сразу в плане реализации, если это реализуемо на Crystal
