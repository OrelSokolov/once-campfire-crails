# 1:1 — браузерный паритет crails ↔ Rails

Цель: crails неотличим от Rails-оракула в headless-браузере. Меряется сьютом
`capybara-tests/` (72 теста, ~130 артефактов на таргет: PNG + нормализованный
HTML на каждый `snap`). Готовность — детерминированный прогон без `missing`,
PNG-совпадение ≥ порога 0.2% попиксельно (в пределе — побайтово, как у
rails-vs-rails), HTML-diff = 0.

## Текущее состояние (прогон 2026-10-16)

| Таргет | Тесты | Failures | Errors | PNG | HTML |
|---|---|---|---|---|---|
| rails (оракул) | 72 | 0 | 1 | — | — |
| crails | 72 | 0 | 0 | **8/65** | **12/64** |

- rails: единственный error — `rooms/test_broken_room_survives_a_missing_author`
  падает НА САМОМ RAILS (500, `messages_helper.rb:97`,
  `message.creator.attributes` на nil). Это баг оракула, не чиним; из-за него
  compare показывает 2 missing (rails-артефакт broken-room не создался) +
  1 png (avatar-david — см. ниже).
- crails: полный прогон детерминированно зелёный — 72/72, включая broken-room
  (наш рендер корректно подставляет плейсхолдер `.message--failed`).
- Сервер по-прежнему умирает (signal 11, P0 из пункта 1) ~1 раз за прогон,
  но harness авторестартует его на том же дата-дире, и тесты проходят.

Прогресс HTML-паритета за сессию: 0/64 → 12/64 байт-идентичных; суммарный
объём диффов сократился в разы (например hq-комната 1818 → 430 строк,
quick-boost 4476 → ~500, plain-message → 0).

## Что было починено (2026-10-16)

Функциональное (всё проверено полным прогоном 72/72):

1. **Reconcile оптимистичных сообщений** — `public/assets` устарел: при
   повторном `assets:precompile` рельсы пересобрали 8 JS-файлов с новыми
   дайджестами (`messages_controller-3a84abbb.js` с reconcile-кодом против
   нашего старого `3d90944a.js` без него). Ресинк файлов + `importmap.html` +
   `manifest.json`. Урок: после каждого `assets:precompile` в
   bench-workspace/once-campfire сверять дайджесты (diff manifests).
2. **`test_wrong_password_shows_error`** — render_login не отдавал
   `flash.now[:alert]` («Too many requests or unauthorized.», markup из
   application.html.erb:38-48).
3. **`test_deep_link_to_a_message_anchors_it`** — не было роута
   `/rooms/:id/@:message_id` и page_around-логики (40 до якоря + якорь + 40
   после). Заодно роутер action_pack_cr научился сегментам-параметрам с
   литеральным префиксом (`@:message_id`).
4. **`test_watercooler_pages_through_history_on_scroll`** — три причины:
   `data-messages-page-url-value` был относительным (JS-пагинатор делает
   `new URL(value)` без базы → TypeError); ответ `messages#index` был
   обёрнут в doctype/main (Rails отдаёт голую коллекцию партиалов); не было
   204 на пустую страницу и `?after=`-пагинации.
5. **`test_sign_out_returns_to_login`** — не было `DELETE /session` и
   `sessions#destroy`.
6. **`test_creating_a_bot_yields_a_working_posting_url`** — список комнат бота
   на /account/bots: Rails `bot.rooms.without_directs.ordered` (без Direct, по
   LOWER(name)), мы сортировали по id и включали Direct; grant membership при
   создании бота искал `type='Open'`, а сид хранит `Rooms::Open` (молча 0
   комнат).

Layout-байтовое (нормализованный HTML, compare):

- **head**: точный порядок метатегов application.html.erb (view-transition,
  theme-color ×2, apple-mobile-web-app-capable, vapid-public-key), убран
  csrf-token meta (у Rails его нет — Sec-Fetch-Site), custom-styles до
  importmap, обе current-user меты на одной строке.
- **lightbox-диалог** в конце body (body_close/page_close) — всех страниц.
- **`translation_button`** (details/popup со словарями переводов) — общий
  хелпер ChatLayout, порт TranslationsHelper со всеми 12 ключами.
- **login-страница** — байт-идентична (форма, инпуты Rails-формы,
  mailto `"Name" <mail>`, `/account/logo?v=`, ERB-пробелы вида
  `</button>      </fieldset>`).
- **message_dom/actions/boosts/presentation** — переносы строк по ERB;
  share-кнопка вложений `hidden=""`; boost span БЕЗ статических
  aria-describedby/tabindex (их ставит boost_delete JS только на бусты
  текущего юзера); `_method` input без autocomplete. presentation-тесты
  (plain/code/table/mention/opengraph/bot/deactivated/rich) — байт-идентичны.

## Что осталось (по убыванию эффекта)

   сейчас hq=430 строк): 
   - nav: блок notifications/involvement (~75 строк markup: turbo-frame
     involvement, dialog «Notifications aren't allowed», Safari/Linux/PWA
     help details) — у нас упрощённый involvement;

   - composer живёт ВНУТРИ `<footer id="footer">` (rooms/show: footer

2. **Вложения** (file/video/image-attachment, 13–38 строк):
   - подпись blob-URL в `/rails/active_storage/blobs/redirect/<sig>/...`

   перевод кнопок уже есть, остаются формы ввода/переносы/порядок блоков —
   механический порт по артефактам.
4. **PNG 8/65** — большая часть попиксельных расхождений уйдёт с HTML
   (до фиксации скелета комнат мерить бессмысленно).
5. **missing 2**: broken-room (баг оракула — на rails артефакт не создаётся);
   `avatar-david.png` — проверить, пишет ли rails этот артефакт вообще

## Запуск / отладка (окружение после смены asdf → rvm)

```bash
crystal build src/app.cr -o bin/app --release -Dwithout_mt   # из корня
cd capybara-tests
TARGET=crails PARITY_RUBY=$HOME/.rvm/rubies/ruby-4.0.4/bin/ruby bash bin/run        # полный прогон
TARGET=crails PARITY_RUBY=... bash bin/run -n "/test_quick_boosting/"               # один тест
env -u GEM_HOME -u GEM_PATH PATH="$HOME/.rvm/rubies/ruby-4.0.4/bin:$PATH" \
  bash -c 'ruby -S bundle exec ruby harness/compare.rb rails crails'                # отчёт compare
```

Важно:
- asdf-руби нет; всё через `PARITY_RUBY=$HOME/.rvm/rubies/ruby-4.0.4/bin/ruby`
  и `env -u GEM_HOME -u GEM_PATH` (иначе GEM_PATH указывает на 3.4.5).
- Rails-бенч требует `assets:precompile`; после него сверять дайджесты
  ассетов с нашим `public/assets` (см. «Что было починено» п.1).
- Отладочный сервер поднимать с env как в `capybara-tests/harness/boot.rb`
  (`CAMPFIRE_STORAGE_ROOT`, `CAMPFIRE_JOBS_DB`, …); убивать по PID из ps.

Детали harness, гарантии детерминизма и список нормализаций — в
`capybara-tests/README.md`.
