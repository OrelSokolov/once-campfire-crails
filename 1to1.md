# 1:1 — браузерный паритет crails ↔ Rails

Цель: crails неотличим от Rails-оракула в headless-браузере. Меряется сьютом
`capybara-tests/` (72 теста, ~130 артефактов на таргет: PNG + нормализованный
HTML на каждый `snap`). Готовность — детерминированный прогон без `missing`,
PNG-совпадение ≥ порога 0.2% попиксельно (в пределе — побайтово, как у
rails-vs-rails), HTML-diff = 0.

## Порядок фиксов

### 1. Сегфолт `bin/app` — P0, блокер валидации всего остального

`bin/app` падает (signal 11) во время многосессионных live-тестов; те же тесты
поодиночке проходят — краш кумулятивный, триггер не в одном запросе.
Harness это переживает (авторестарт в `before_setup`), но тест, во время
которого сервер умер, не пишет артефакты → каскад `missing` (без авторестарта
было ~60 упавших тестов).

Что делать: воспроизвести вне сьюта (многосессионный live-сценарий в цикле,
`PARITY_KEEP=1` + core dump / адресный лог), найти накопительный ресурс
(фибры CableBus? WS-соединения?泄漏 в action_cable.cr?). Критерий: полный
прогон сьюта без единой смерти процесса (0 missing по причине краша).

### 2. Edit-фрейм — P1, редактирование сообщений сломано целиком

`turbo-frame[id^='edit_message_']` не становится `complete`; сьют ждёт его в
`settled_snap` и падает по таймауту. Затронуты как минимум:
`messaging/test_editing_own_message`, `live/test_edits_propagate_to_the_other_session`
(оба — missing), плюс это размазывает diff по всем страницам с сообщениями.

Что делать: сверить рендер edit-формы и Turbo-обработку PATCH с Rails
(`app/views/messages/_edit` + turbo-stream ответ), проверить, что фрейм
получает корректный src/response. Критерий: оба теста доходят до `snap` и
проходят.

### 3. Бусты — P1, фича не рендерится

В DOM нет `[data-emoji]` и `.message__boost-btn` в меню сообщения. Затронуты:
`messaging/test_quick_boosting_with_an_emoji`, `messaging/test_custom_boost_with_text`,
`live/test_boosts_propagate_to_the_other_session`,
`presentation/test_boost_row_with_emoji_and_text_boosts` (все — missing).

Что делать: сверить partial бустов и JS-меню сообщения с Rails
(`message__boost-btn`, quick/custom boost), live-ретрансляцию буста в комнату.
Критерий: 4 теста выше доходят до `snap` и проходят.

### 4. Точечные расхождения — P2

| Что | Тест | Симптом |
|---|---|---|
| Autolink в сообщениях | `messaging/test_sending_a_link_autolinks_it` | падает до снимка |
| Welcome-страница одинокого юзера | `sidebar/test_member_of_no_rooms_sees_the_welcome_page` | падает до снимка |
| Broken-room | `rooms/test_broken_room_survives_a_missing_author` | нет `.message--failed` |
| OG-unfurl | `presentation/test_opengraph_unfurl_card` | карточка не совпадает |

Остальные missing (`auth/test_sign_out_returns_to_login`,
`auth/test_wrong_password_shows_error`, `account/test_creating_a_bot_yields_a_working_posting_url`,
`rooms/test_deep_link_to_a_message_anchors_it`, `rooms/test_watercooler_pages_through_history_on_scroll`)
— разложить на сегфолт vs функциональные после P0: перегон сьюта на
починенном сервере сам покажет, какие выжили.

### 5. Систематический HTML-diff — P2, после функциональных фиксов

HTML расходится на всех 64 страницах, включая логин (175 строк diff: другие
метатеги, importmap в другом месте). Это не норма для цели 1:1 — выровнять
layout crails с Rails побайтово (порядок метатегов, расположение importmap,
прочая структурная разница), а не прятать её в нормализацию harness'а.

### 6. PNG-диффы остаточные — P3

После 1–5 переснять compare и разобрать оставшиеся попиксельные расхождения
по категориям (крупнейшие: sidebar 0.39, presentation/rooms ~0.17 доли
пикселей). Часть уйдёт сама с фиксами выше (бусты/edit меняют DOM комнат).

## Определение готовности

1. `TARGET=crails bin/run` ×2 подряд: 72 теста, 0 failures, 0 errors,
   0 смертей сервера.
2. `compare rails crails`: missing 0, HTML 64/64, PNG ≥ 65/65 в пороге 0.2%
   (базлайн-цель — побайтово, как rails-vs-rails).
3. `1to1.md` обновлён итоговыми цифрами.

## Запуск / отладка

```bash
cd capybara-tests
TARGET=crails bin/run -n /test_quick_boosting/   # один тест
bin/parity 09_live_test.rb test_boosts_propagate # быстрый прогон с PARITY_KEEP=1
bundle exec ruby harness/compare.rb rails crails  # отчёт
```

Детали harness, гарантии детерминизма и список нормализаций — в
`capybara-tests/README.md`.
