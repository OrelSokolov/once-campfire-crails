## Что было починено (2026-10-16)

Функциональное (всё проверено полным прогоном 72/72):

1. **Reconcile оптимистичных сообщений** — `public/assets` устарел: при
   повторном `assets:precompile` рельсы пересобрали 8 JS-файлов с новыми
   дайджестами (`messages_controller-3a84abbb.js` с reconcile-кодом против
   нашего старого `3d90944a.js` без него). Ресинк файлов + `importmap.html` +
   `manifest.json`. Урок: после каждого `assets:precompile` в
   bench-workspace/once-campfire сверять дайджесты (diff manifests).
2. **`test_wrong_password_shows_error`** — render_login не отдавал
   `flash.now[:alert]` («Too many requests or unauthorized.», markup из
   application.html.erb:38-48).
3. **`test_deep_link_to_a_message_anchors_it`** — не было роута
   `/rooms/:id/@:message_id` и page_around-логики (40 до якоря + якорь + 40
   после). Заодно роутер action_pack_cr научился сегментам-параметрам с
   литеральным префиксом (`@:message_id`).
4. **`test_watercooler_pages_through_history_on_scroll`** — три причины:
   `data-messages-page-url-value` был относительным (JS-пагинатор делает
   `new URL(value)` без базы → TypeError); ответ `messages#index` был
   обёрнут в doctype/main (Rails отдаёт голую коллекцию партиалов); не было
   204 на пустую страницу и `?after=`-пагинации.
5. **`test_sign_out_returns_to_login`** — не было `DELETE /session` и
   `sessions#destroy`.
6. **`test_creating_a_bot_yields_a_working_posting_url`** — список комнат бота
   на /account/bots: Rails `bot.rooms.without_directs.ordered` (без Direct, по
   LOWER(name)), мы сортировали по id и включали Direct; grant membership при
   создании бота искал `type='Open'`, а сид хранит `Rooms::Open` (молча 0
   комнат).

Layout-байтовое (нормализованный HTML, compare):

- **message_dom/actions/boosts/presentation** — переносы строк по ERB;
  share-кнопка вложений `hidden=""`; boost span БЕЗ статических
  aria-describedby/tabindex (их ставит boost_delete JS только на бусты
  текущего юзера); `_method` input без autocomplete. presentation-тесты
  (plain/code/table/mention/opengraph/bot/deactivated/rich) — байт-идентичны.

## Что осталось (по убыванию эффекта)

Сегфолт live-сьютa (актуальная форензика — раунд 3, commit c83ce8a,
подробности и инструменты: `docs/segfault-investigation/README.md`):

- Что делать: воспроизвести вне сьюта (многосессионный live-сценарий в цикле,
  `PARITY_KEEP=1` + core dump / адресный лог), найти накопительный ресурс.
  Критерий: полный прогон сьюта без единой смерти процесса (0 missing по
  причине краша).
- **Механизм уточнён (раунд 3, 2026-10-16):** прежний вывод «ret в
  `Fiber::swapcontext` резюмит мёртвую фиберу» опровергнут прямым
  breakpoint-замером (все ~2000 resume за прогон корректны, включая
  падавший). Реальная сигнатура: вход в entry
  `DB::Statement#exec:args<Array(Int64)>` с полностью мусорным контекстом
  (rsi=1 → fault `[rsi+4]`=0x5, rbp=r15=0x29, под rsp нет return address),
  значение-цель перехода отсутствует во всей памяти процесса → прыжок
  вычисленный (главный кандидат — unwind landing pad при исключении
  Crystal). sqlite3_close не вызывался; кадры sqlite на стеке жертвы —
  stale-мусор рециклированного региона.
- **Исключено экспериментами (bisect приложения):** конфигурация пула
  (`max_pool_size=1` и 5/5); fair_busy; jobs-воркеры (`JOB_CONCURRENCY=0`);
  Action Cable целиком (WS → call_next); ping-loop кабеля; WriteQueue
  (perform inline); `sqlite3_close` при живом statement (PLT-лог).
  Триггер — в базовом HTTP-пути запроса (request fiber + AR/crystal-db пул +
  middleware) при churn'е соединений. Также: libc-overflow
  (`MALLOC_CHECK_=3` молчит), REGEXP-колбэк.
- **Репорт для апстрима:** пакет в `docs/segfault-investigation/` — README.md
  (статус + механизм + bisect + история), ISSUE.md (черновик issue), repro.cr
  (синтетика v3: HTTP + churn клиентов + пул SQLite — пока НЕ крашится),
  bpx.py (адаптивный gdb-инструментарий), dumps/ (эталонные дампы).
- **Следующие шаги:** 1) ловить вычисленный прыжок (bp на
  `_Unwind_RaiseException` / landing-pad); 2) проверить многопоточность на
  момент краша (`info threads`); 3) автономный repro (исключение в
  select/канале на рециклированном стеке + crystal-db retry).

### 2. Edit-фрейм — P1 закрыт (2026-10-22)

Само редактирование починено ещё в 308a06b (message_path →
room_message_path; 500 на edit turbo-frame). 2026-10-22 добит
байт-паритет DOM вокруг edit-флоу — все три снапа фильтра /edit/
(messaging/edited, live/live-edit, profile/profile-edited) теперь
HTML+PNG байт-идентичны оракулу:

- **append-стримы сообщений**: у Rails `@message_html =
  render_to_string` партиала кончается ровно `</div>` (Erubi глотает
  переводы после `<% end %>`); наш message_dom кончался `</div>\n`,
  и Turbo аппендил в контейнер текстовый узел-пробел (в нормализованном
  DOM: `</div></div>` склеены у оракула, у нас с переносом). Хвостовой
  `\n` срезается (`.chomp`) в трёх местах: HTTP-ответ messages#create
  и by_bots#bot_create, cable-broadcast MessageCreator.broadcast
  (бусты уже были корректны: boost_dom + "\n").
- **by_bots#bot_create двойной broadcast**: MessageCreator.create!
  уже вещает append, явный broadcast_append_to в контроллере давал
  второй дубль в cable (у Rails ровно один — broadcast_create внутри
  super). Явный вызов убран.
- **profile-страница**: profile_nav склейка `<img><span>` (нет `\n`
  после иконки logout) + три потерянные blank-строки в
  users/profiles/show.html.erb (Erubi глотает один `\n` после
  `<% end %>`, оставшиеся переносы Rails сохраняет; при порте вьюхи
  blank-строки выпали — `</form><form` склейки).

тесте: execute_script не ждёт загрузки edit-фрейма, editor null;

## Запуск / отладка (окружение после смены asdf → rvm)

```bash
crystal build src/app.cr -o bin/app --release -Dwithout_mt   # из корня
cd capybara-tests
TARGET=crails PARITY_RUBY=$HOME/.rvm/rubies/ruby-4.0.4/bin/ruby bash bin/run        # полный прогон
TARGET=crails PARITY_RUBY=... bash bin/run -n "/test_quick_boosting/"               # один тест
env -u GEM_HOME -u GEM_PATH PATH="$HOME/.rvm/rubies/ruby-4.0.4/bin:$PATH" \
  bash -c 'ruby -S bundle exec ruby harness/compare.rb rails crails'                # отчёт compare
```

Важно:
- asdf-руби нет; всё через `PARITY_RUBY=$HOME/.rvm/rubies/ruby-4.0.4/bin/ruby`
  и `env -u GEM_HOME -u GEM_PATH` (иначе GEM_PATH указывает на 3.4.5).
- Rails-бенч требует `assets:precompile`; после него сверять дайджесты
  ассетов с нашим `public/assets` (см. «Что было починено» п.1).
- Отладочный сервер поднимать с env как в `capybara-tests/harness/boot.rb`
  (`CAMPFIRE_STORAGE_ROOT`, `CAMPFIRE_JOBS_DB`, …); убивать по PID из ps.

Детали harness, гарантии детерминизма и список нормализаций — в
`capybara-tests/README.md`.
